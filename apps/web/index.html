Flock Realtime Collab

Local-first realtime collaboration. Peers that always converge.

A sequence CRDT and a last-writer-wins map written from scratch in TypeScript, a sync protocol built on state vectors, a WebSocket relay that persists every room to disk, and a collaborative editor with a shared whiteboard and live cursors.

Open the Partition Lab Run the editor locally

The Partition Lab runs entirely in this page: three peers, a simulated network you can cut, slow down and make lossy. The editor needs the Node server, which you start with one command.

How it converges

Every character has an identity

Text is an RGA: each character is an item with a unique id (replica, seq) and a Lamport time, inserted after a known origin. Concurrent inserts at the same spot are ordered by Lamport time, then replica id, so every peer picks the same order. Deletes leave tombstones.

Operations wait for their causes

An operation is applied only after the operations it depends on. Anything that arrives early waits in a buffer; duplicates are recognised by id and ignored. Any delivery order gives the same document.

State vectors, then deltas

Peers exchange state vectors (replica to highest sequence number) and send back only what the other side lacks, in a compact binary format. Periodic anti-entropy repairs messages lost in transit.

Offline is the normal case

Edits made without a connection queue up and replay on reconnect. The editor keeps each room in local storage, and the server appends every update to a checksummed log that survives restarts.

Architecture

Run it locally

git clone https://github.com/TIENDUNG21/flock-realtime-collab
cd flock-realtime-collab
npm ci
npm run server     # ws://localhost:5130
npm run dev:web    # http://localhost:5135/editor.html

Open the editor in two browser windows to see text, shapes and cursors move between them. Stop the server, keep typing, start it again: both sides catch up.

What is tested

  • Property tests: 3 to 5 replicas, random concurrent edits, delivery out of order, late and duplicated; all replicas end identical.
  • Merges are idempotent and commutative.
  • Simulated networks with partitions, loss and duplication always heal.
  • The decoder rejects every truncation and random input with a clear error.
  • A real server with real WebSocket clients: concurrent edits, an offline client, restarts.
